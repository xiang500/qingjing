# 初赛反馈与优化记录

> 初赛总分 **77**，评语：**「内容组织有条理，加载体验可以再优化下」**。
> 本文记录我们针对这条反馈做的每一项改动，以及可验证的前后数据。
> 对应提交：`qingjingTest3` → `qingjingTest4` → `qingjingTest5`。

## 一、把评语拆成两个可执行的问题

| 评语 | 我们的理解 | 对应动作 |
| --- | --- | --- |
| **加载体验可以再优化** | 首屏与路由切换的**体积 / 等待**明显 | 移除 3D 与姿态识别重依赖、路由懒加载、分包、图片压缩（见第二节） |
| **内容组织有条理**（肯定） | 结构与文案已经过关 | 保留，并把「有条理」升级为「**内容具体**」：真实照片、真实数据、可量化指标（见第三节） |

## 二、加载体验：从 34.8 MB 到 3.16 MB

初赛版本（`qingjingTest2`）为了做「实时试衣镜」，引入了 Three.js 程序化数字人与 MediaPipe 端侧姿态识别。
这两块都不是小体积：

| 资源 | 体积 | 是否在首屏路径 |
| --- | --- | --- |
| `public/mediapipe-wasm/`（wasm 运行时） | **26.8 MB** | 进入试衣镜即加载 |
| `public/models/pose_landmarker_lite.task`（姿态模型） | **5.8 MB** | 同上 |
| `public/models/` 其余（人台 GLB 等） | 0.9 MB | 同上 |
| `three` + `gsap` | 约 600 KB（gzip 约 150 KB） | 试衣镜路由 |

**这就是「加载体验」扣分的直接原因**：进一次试衣镜要拉 30 MB+，弱网/校园网下体感就是「卡、一直转圈」。

### 改法

1. **下掉 3D 与摄像头链路**：删除 `MirrorScene.ts`（1394 行）、`usePoseTracker.ts`、
   `public/models`、`public/mediapipe-wasm`、`fetch:assets` 脚本，以及 `three` / `gsap` / `@mediapipe/tasks-vision` 依赖。
2. **替换为 2D 造型板**：单品以平铺卡按品类落格（CSS Grid，几何校验零重叠），
   配色评分由本地规则计算，不依赖模型推理，也不占用首屏。
3. **路由全部懒加载**：首页 / 顾问 / 工作台 / 社区 / 看板 / 后台 / 个人中心各自 chunk。
4. **大库单独分包**：ECharts 拆成独立 chunk（gzip ≈ 191 KB），**只有进入数据看板才下载**。
5. **图片规范化**：演示照片统一裁成 4:5 / 3:4、JPEG q88、长边 ≤ 800 px，
   实拍素材总量 1.75 MB（21 张），页面按需懒加载。

### 结果（同一台机器实测）

| 指标 | 初赛版本（Test2） | 当前版本 |
| --- | --- | --- |
| 生产构建 `dist` 体积 | **34.8 MB** | **3.16 MB** |
| 首屏主 chunk（gzip） | — | **≈ 69 KB** |
| 进入数据看板额外下载 | 全量打包 | ECharts chunk gzip ≈ 191 KB（仅首次） |
| 进入搭配工作台 | three + wasm + 模型 ≈ 33 MB | 27 KB JS（路由 chunk） |
| 首屏 JS 请求数 | 全量 | 7 个页面按需，首屏仅主包 + http 封装 |

> 说明：当前版本的 3.16 MB 里有 1.75 MB 是**演示照片**（21 张，为了「内容具体」新增），
> 纯代码体积约 1.4 MB。

## 三、内容具体：从「有功能」到「有数据、有素材」

初赛版本功能齐全但偏「框架演示」：插画是占位图、社区只有 1 条帖子、数据看板没有业务指标。
这一轮补齐了能体现「真实使用」的部分：

| 方向 | 新增内容 |
| --- | --- |
| 真实素材 | 12 件实拍单品（名称 / 品牌 / 材质 / 价格与照片一致）、9 张整套穿搭图作为套装封面 |
| 社区 | 6 条真实分享，3 位示例作者，标签 / 点赞 / 评论完整（原来只有 1 条占位帖） |
| 衣橱数据 | 单次穿着成本 CPW（平均 / 最划算 / 最该处理 + Top 8 排行）、365 天穿着热力图 |
| AI 可度量 | 推荐曝光 / 采纳 / 采纳率闭环，看板可见 |
| 知识库 | 12 条穿搭知识入库，管理端可增删改，写后 RAG 索引热刷新 |

## 四、视觉与信息架构

初赛版本是固定暗色主题，页面内容平铺。这一轮：

1. **四季光场**：春·新绿 / 夏·海盐 / 秋·杏黄 / 冬·夜雪四套色盘，30 秒自动轮播，
   换季只改 `<html data-season>` 与 `data-scheme` 两个属性；纯 CSS 液态玻璃材质，零图片依赖。
2. **页面节奏**：固定间距与圆角标度（`--space-1..8`、`--radius-xs..lg`），
   页面按「拆块 → 组间留白 → 同级错落 → 操作靠明暗对比突出」组织，取代原来的一长条平铺。
3. **搭配工作台**：从「人台 + 贴图」改为「造型板」，卡片由网格布局决定位置，
   几何校验 14 个场景**零重叠**，图注完整可读。
